# S2 1.1 The Phases of a Project Life Cycle: The Project Defining Phase

## Learning Objectives

Identify each phase of a project.

## The Project Life Cycle

The project life cycle is a core concept in PMBOK 7. It provides a structured way to manage a project from conception to completion. The project life cycle is not a one-way street. It is a series of phases that a project progresses through from start to finish, often revisiting and iterating on previous phases. It essentially acts as a framework for managing the project throughout its entire duration, with the key phases being defining, planning, execution, and closure. The project life cycle is integrated into the Development Approach and Life Cycle performance domain, emphasizing the importance of aligning its development approach with its life cycle phases to deliver business value throughout the project. We will also consider the models, methods, and artifacts, or the tools and tailoring used to assist with developing and moving through the phases of the project life cycle. Each project is unique in the specifics of the activities that must be completed as it moves through the project phases toward completion, but we know that overall, there are general ways to organize and group those activities. At a high level, the project life cycle can be described as having a defining phase, a more detailed planning phase, a phase when the deliverables are created, and a closing phase where the completed project is turned over to the customer and the project reaches conclusion. To gain a better understanding of how the activities vary across the project’s life cycle, the activities are grouped into phases. The four general phases are identified as defining, planning, executing, and closing.

other factors that will change throughout the life of the project. To help illustrate these changes across the life of a project, consider how the level of resources will vary. During the defining phase, there will likely be few people involved in the initial development of the project proposal and the evaluation of which projects will be undertaken. At this time of the project, the relationship with the customer begins to be defined, and a project charter or contract for the project begins to be formulated. As the project moves into the planning phase, subject matter experts may be added to the project team in order to carefully plan and budget the activities that will need to be completed. In the execution phase, large numbers of people may be added to the project in order to complete the work. In the final closing phase, the team members will have completed the major work, and a smaller team may remain to turn the results over to the customer.

## The Project Defining Phase

The phases occurring in the project are explained in the flowchart. The four phases are defining, planning, executing, and closing. The defining phase is where the idea is formalized into a project proposal. During the project defining phase, the idea for the project is formalized into a project proposal and the decision on whether the project will be selected for implementation is made. The project defining phase begins when an idea for a project is identified by a company. Not all ideas are good for the company, so during this phase, the idea is developed into a project proposal with enough detail that the company leadership can determine if the project should be completed.

## Developing the Project Proposal

Developing the proposal will require company resources (cost) in order to gather enough information to make a selection decision, so not all ideas will even move into the defining stage. If an idea is deemed worthy of further evaluation, then high-level information will need to be gathered. At a minimum, the project proposal will need to include the following information:

- major project outcomes and deliverables
- how the project will be completed
- a high-level estimate of the cost
- a high-level estimate of the completion time
- the reason that the project should be undertaken
- the benefits that the company will gain by completing the project
- what resources will be needed
- any risks that could derail the project
- major stakeholders and their roles in the project
- where the decisions are made by the deciding customer or stakeholder

This information feeds the project selection process. If the project is selected for implementation, this information is written into a formal document called the project charter.

## The Project Charter

The project charter defines and documents the project’s existence and will be described in more detail later. A small project may not require a formal project charter, but the project will still need to be defined sufficiently to be moved forward. The selection (or rejection) of the project and creation of the project charter mark the conclusion of the project defining phase. If the project is selected, it moves into the project planning phase.
