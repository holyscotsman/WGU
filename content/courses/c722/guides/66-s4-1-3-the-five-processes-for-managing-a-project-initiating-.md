# S4 1.3 The Five Processes for Managing a Project: Initiating and Planning

## Learning Objectives

Identify the five processes for managing a project.

## The Five Processes

The project life cycle, introduced earlier in this course, provided a high-level view of the work that needs to be done in order to complete a project. The project life cycle is managed by using five processes: initiating, planning, executing, monitoring and controlling, and closing. These logical groups of processes outline what must occur to manage the project.

Depending on project complexity, completing a project can require extensive management of a large number of activities. These activities occur as part of larger processes, which ensure successful project completion. They include things like selecting suppliers, analyzing bids, communicating with stakeholders, gathering requirements, and selecting team members. To help organize the activities, they are organized into five process groups. The five process groups align with the project life cycle discussed previously.

The process groups are organized chronologically across the life of the project and fit with the typical project life cycle of define, plan, execute, and close. Notice that the processes related to planning, executing, and monitoring and controlling are identified as iterative since they will be repeated as needed to revise the plan and re-execute until the project is ready for closure.

The five processes of managing a project are logical groups of processes that outline what must occur to manage a project. Depending on project complexity, completing a project can require extensive management of a large number of activities. These activities occur as part of larger processes that ensure successful project completion. The project process group of the project life cycle includes the methods of initiating, planning, executing, monitoring and controlling, and closing. The four phases of the project life cycle are define, plan, execute, and close.

## The Processes of Initiating

The processes of initiating involve defining the project and determining which projects the organization will undertake. These activities often occur prior to the selection of the project team or the project manager.

The project evaluation methods used to select the project discussed earlier are completed as part of the initiating process. These preliminary steps are important since they will set the trajectory for the project. If the project is not clearly defined and developed to satisfy a specific business need, then the project may not reach a successful conclusion. When the initiating processes are completed, if the project is approved to move forward, the project charter is issued and signed by the project sponsor.

The processes completed during initiating include the following:

documenting the business need for the project and what problem the project will solve

defining the project

evaluating project proposals

completing project selection

identifying major stakeholders

creating the project charter

## The Processes of Planning

If the project is approved through the initiating processes, it goes on to planning. Often a project manager has already been on the project, but sometimes they are chosen and assigned during the planning phase. The project manager will begin assembling the team to create the project plan. Additional team members may be required to gather information from stakeholders, identify the project activities, estimate costs and time, and document the planning areas.

Traditional project management assumes that the project outcomes have been sufficiently defined such that the activities required to complete them can be reliably identified and estimated.

The project plan, developed during the planning processes, will be used by the team for project execution. Additionally, the approved project scope, budget, and schedule created through the planning process will become the standard for performance measurement.

Planning has been identified as an iterative process. This means that while project managers want the plan to be as complete as possible, they know that changes will be identified later that will require the team to replan portions of the project.

The processes completed during planning include the following:

documenting all customer requirements and deliverables

estimating resource needs

finalizing the project scope

finalizing the project budget

finalizing the project schedule

creating the work breakdown structure

creating the network diagram

creating the activity list

writing the plan for specific areas (quality, communications, human resources, procurement, change management, scope management, cost management, schedule management, risk management, etc.) A Work Breakdown Structure, WBS lists the project activities and tasks and identifies how they fit together and where they fit on a calendar.

When the plan, scope, budget, and schedule are agreed upon by the project manager, project team, customer, and other key stakeholders, the work can begin.
