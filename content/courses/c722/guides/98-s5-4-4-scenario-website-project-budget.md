# S5 4.4 Scenario: Website Project Budget

## Learning Objectives

Prepare a calendarized project budget.

Now you will follow the budget creation process from the WBS through to the calendarized budget. Using an e-commerce website project, recall that the WBS decomposes the project into smaller work activities and tasks. In this example, the overall project is "Website Project," which is at the top of the WBS (Level 0) shown using the hierarchical tree structure. The overall project has been decomposed into five major deliverables shown in Level 1. Based on historic percentages for the cost of the work, the overall budget of $100,000 has been allocated to the major deliverables using the apportion method. Often, the organization will set the labor cost based on a fully absorbed cost of an individual’s time based on organization policies. This will often include salary plus bonuses plus benefits plus designated overheads. They may call this the FTE, or full-time equivalent, cost of an individual hour or fully absorbed cost. You will multiply this number by the number of work hours estimated to get the labor cost.

As the work is further decomposed into Level 3, Level 4, and so on, the budget is further distributed. For this example, you will construct the budget using the Level 1 estimates.

The total budget for a website project is $100,000. There are five subcategories branching from the total. The categories are design, which is estimated at $20,000, and programming, which is estimated at $30,000. Testing is estimated at $20,000, and documentation is estimated at $15,000, followed by user training, which is estimated at $15,000. A simple budget would be the total project estimate of $100,000. A calendarized budget requires that the timing of the expenditures be identified. For this example, the durations of each activity and the order that the activities occur has been included as a network diagram. Network diagrams will be discussed in another lesson, so for now you just need to know that the circles designate the work activities, and the arrows show the order in which they will occur. The designation "1w" in each circle is the estimate of how long the activity will require to complete. In the case of design, the duration is expected to take one week, the cost is $20,000, and it is the first activity in the project.

There are five ovals shown with connecting lines. The first oval, labeled 1.1 Design 1w, leads to 1.2 Programming 2w and 1.4 Documentation 3w. The Design oval leads to 1.3 Testing 1w. The Documentation and Testing ovals both lead to the final oval labeled 1.5 User Training 1w. To build the calendarized budget, the information from the WBS, budget, and network diagram are combined. The first column is the list of activities from the WBS. The network diagram is then used to identify when the activities occur. For this example, the top row is labeled Week 1, Week 2, etc. This would be updated once the project start date is confirmed. For cash planning purposes, providing the week that the expenditure will occur is normally sufficient.

Since the design work will all occur during Week 1, the total cost estimate of design ($20,000) is shown in the Week 1 column on the Design row. The network diagram shows that programming can begin after design. Programming has a duration of two weeks, so the cost estimate of $30,000 is divided evenly between Week 2 and Week 3. Documentation occurs after design on the network diagram, takes 3 weeks, and costs $15,000, so it is shown as a budgeted cost of $5,000 in Weeks 2, 3, and 4. Testing appears in the network diagram after programming, so it is scheduled as an expenditure in Week 4. Its one-week duration requires that all of its $15,000 budgeted cost be shown in Week 5.

The calendarized budget can be summed for each week so that money can be made available to pay those costs when they occur. Notice that across the five weeks of the project, the weekly costs vary depending on the activities scheduled for that week. This is the start of the cash flow requirements of the project.
