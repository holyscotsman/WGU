# S5 1.1 The Purpose of Project Planning

## Learning Objectives

Describe the purpose of project planning.

## Overview

Planning is about developing a plan to create an output or project deliverable, ultimately delivering the intended outcome or value expected by the organization and its stakeholders. Let’s explore how finalizing the project charter will move the project from the defining phase to the planning phase.

## The Project Charter and Its Usefulness

Project charter written on a whiteboard with the following words written around it: scope, objective, measurements and assumptions, restrictions, major participants, project manager authority. syahrir maulana/iStock / Getty Images Plus via Getty Images. The project charter’s most important function is that it authorizes the project. It is, essentially, the contract document showing the agreement by the key stakeholders created in the defining phase. Without this, no work on the project can occur. The project charter is a relatively brief document that provides a very high-level view of what the project entails. Here is an example of a project charter template from the Centers for Disease Control and Prevention (CDC):

This website has instructions from the Agency for Healthcare Research and Quality (AHRQ) on how to write a project charter on pages 174–175:

From the previous two examples, you can see that the amount of detail included in the project charter may vary from one or two pages to a dozen or more. Regardless, all project charters contain enough information to understand who the project sponsor and project manager are, the purpose of the project, and a general idea of the scope, budget, and schedule. Project charters often contain the following:

- project name
- sponsor name
- project manager name
- simple, yet precise, statement of the project
- objective
- scope
- performance measures
- major milestones
- major deliverables
- assumptions
- constraints

## Project Planning Documents

In a previous lesson, you learned about the triple constraints and how a change to any one constraint can impact the other two. You saw how important it is to fully understand and define scope, cost, and budget. The project scope includes several items that must be further broken down into components. Without identifying, understanding, and specifying each aspect of the project, it is impossible to develop an accurate budget or schedule. Numerous documents must be developed in order to ensure proper identification of all items and to ensure that everything is included.

The paper is marked with three checkboxes, and a pencil is laid on top. deeaf/iStock / Getty Images Plus via Getty Images. Checklists are one method of ensuring that all needed documents are written. A checklist only ensures that the actions on the list are addressed. The checklist is only as good as the completeness of the items listed and the team’s attention to the work being done.

It does not guarantee that the items have been thoroughly addressed or meet required performance of quality standards. Also, this sample checklist may not be applicable to every project you encounter. A checklist is a tool to help make sure all items are included. Checklists must also be reviewed for completeness and applicability. Ambiguous or unnecessary items must be excluded from the checklist. Checklists are one way of monitoring activities and tasks that have been addressed. Because they do not indicate the completeness or the quality of the work, other planning documents must also be utilized. Earlier in this lesson, you saw a (partial) list of the responsibilities of the project manager. Ideally, there should be artifacts and documentation for each of these activities describing how they will each be accomplished. In other words, a plan for each and every one of the areas for which the

project manager is responsible. This helps the project manager track the work and ensure everything is covered. In addition, if there is a change of personnel (a new project manager, for example), then the new person can know and understand what needs to be accomplished and how. The project scope and the statement of work (SOW) provide much more detailed descriptions of what must be planned. From these, a work breakdown structure (WBS) is developed, which details each activity that must be completed. The WBS will help identify specific skills, training, and experience needed on the project. This will generate the resource responsibilities matrix (to be discussed in an upcoming lesson). As you will see, the forming of the project schedule through the creation of the WBS and resource responsibility matrix will generate a planning schedule for the number and type of resources required, as well as the duration of each resource. All planning documents are "living" documents. This means that they all need to be periodically reviewed to ensure that the plans are still valid. Approved changes are possible at any time in the project life cycle and can cause plans to change.
